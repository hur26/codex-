# Codex 单任务状态证据

**采集日期：** 2026-07-26

**验证范围：** Windows 版 Codex 桌面端，单个任务、两次 `UserPromptSubmit` 的采集窗口

**探针基线：** `b16390b`

## 方法

1. 在已审批的生命周期 Hook 中运行本地只追加探针。
2. 探针在写盘前删除提示词、回复、工具参数、命令、代码、文件内容、环境变量和认证信息。
3. 对候选身份值仅保存 16 位 SHA-256 指纹，并用独立分析器聚合事件类型和指纹数量。
4. 本文只依据脱敏聚合报告编写，不读取、引用或提交原始探针事件。

聚合报告见
[`2026-07-26-single-task-analysis.json`](./2026-07-26-single-task-analysis.json)。

## 单任务证据

本次共分析 16 个有效事件：

| Hook 类型 | 数量 | 可用于判断 |
|---|---:|---|
| `UserPromptSubmit` | 2 | 新执行轮次开始 |
| `PreToolUse` | 7 | Agent 正在开始一次工具操作 |
| `PostToolUse` | 6 | 一次工具操作结束，任务仍可继续 |
| `Stop` | 1 | 按 Hook 定义作为轮次结束候选 |

数据质量检查：

- 无法读取、超限、格式错误或非对象文件：0
- 无效 Hook、候选身份路径或指纹：0
- 被资源限制截断的记录：0
- 文件数量上限触发：否

身份候选结果：

| 候选路径 | 不同指纹数 | 结论 |
|---|---:|---|
| `$.session_id` | 1 | 符合稳定任务身份候选预期 |
| `$.turn_id` | 2 | 符合轮次候选预期；聚合报告不证明逐轮一一对应 |
| `$.cwd` | 1 | 仅表示项目上下文；多个任务可共享目录 |

全部 16 个事件只有 1 个 `session_id` 指纹，同时出现了 2 个 `turn_id`
指纹。结合 2 次 `UserPromptSubmit`，现有聚合证据支持把 `session_id`
作为同一 Codex 任务的稳定身份候选，把 `turn_id` 作为执行轮次候选。
双任务采集仍需验证不同任务的 `session_id` 是否互不相同。

## 初步状态映射

| 事件 | 标准状态 | Halo 默认表现 |
|---|---|---|
| `UserPromptSubmit` | 执行中 | 对应圆环开始黄色追逐 |
| `PreToolUse` / `PostToolUse` | 执行中、刷新活跃时间 | 黄色追逐保持流动 |
| `Stop` | 轮次结束候选 | 暂映射为绿色完成提示 |

本次采集到 1 个 `Stop`。按 Hook 定义暂作轮次结束候选，但聚合报告不验证它的
事件顺序，也尚未证明它能区分任务永久完成、用户中止或异常结束；生产状态机应
保留超时校准和后续事件修正能力。

## Gate 结果

**单任务候选 Gate：PASS（进入双任务验证）**

- 单任务的 16 个事件中只有 1 个 `session_id` 指纹，符合稳定任务身份候选预期。
- 样本中有 2 个 `turn_id` 指纹和 2 次 `UserPromptSubmit`，符合轮次候选预期；
  聚合报告尚不证明两者逐轮一一对应。
- 已采集到执行开始、工具活动和轮次结束候选信号；聚合报告不主张事件顺序。
- 全部证据满足既定隐私边界。

## 限制与下一步

当前仍未验证：

- `PermissionRequest` 是否能可靠表示等待用户审批。
- 两个并发任务是否具有不同且各自稳定的 `session_id`。
- 异常失败、用户中止、任务重命名和 Codex 重启后的身份连续性。
- `Stop` 与“任务完成”之间是否需要任务列表或超时规则进一步校准。

下一步执行双任务并发采集：在两个任务中制造交错的只读工具活动，比较
`session_id` 指纹是否稳定且互不相同，并确认每个 `Stop` 能归属到正确任务。
只有双任务 Gate 通过后，才进入自动四环绑定与桌面状态机实现。
