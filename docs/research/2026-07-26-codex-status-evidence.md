# Codex 状态身份验证证据

**采集日期：** 2026-07-26

**验证范围：** Windows 版 Codex 桌面端，单个任务、两次 `UserPromptSubmit` 的采集窗口

**探针基线：** `b16390b`

## 方法

1. 在已审批的生命周期 Hook 中运行本地只追加探针。
2. 探针在写盘前删除提示词、回复、工具参数、命令、代码、文件内容、环境变量和认证信息。
3. 对候选身份值仅保存 16 位 SHA-256 指纹，并用独立分析器聚合事件类型和指纹数量。
4. 本文只依据脱敏聚合报告编写，不读取、引用或提交原始探针事件。

聚合报告见
[`2026-07-26-single-task-analysis.json`](./2026-07-26-single-task-analysis.json)。

## 隐私边界

- 原始提示词、回复：未保存
- 工具参数、命令：未保存
- 代码或文件内容：未保存
- 环境变量、认证信息：未保存
- 原始会话 ID、轮次 ID、工作目录：未保存
- 原始探针 JSON：仅位于本机临时证据目录，不纳入 Git

## 单任务证据

本次共分析 16 个有效事件：

| Hook 类型 | 数量 | 可用于判断 |
|---|---:|---|
| `UserPromptSubmit` | 2 | 新执行轮次开始 |
| `PreToolUse` | 7 | Agent 正在开始一次工具操作 |
| `PostToolUse` | 6 | 一次工具操作结束，任务仍可继续 |
| `Stop` | 1 | 按 Hook 定义作为轮次结束候选 |

数据质量检查：

- 无法读取、超限、格式错误或非对象文件：0
- 无效 Hook、候选身份路径或指纹：0
- 被资源限制截断的记录：0
- 文件数量上限触发：否

身份候选结果：

| 候选路径 | 不同指纹数 | 结论 |
|---|---:|---|
| `$.session_id` | 1 | 符合稳定任务身份候选预期 |
| `$.turn_id` | 2 | 符合轮次候选预期；聚合报告不证明逐轮一一对应 |
| `$.cwd` | 1 | 仅表示项目上下文；多个任务可共享目录 |

全部 16 个事件只有 1 个 `session_id` 指纹，同时出现了 2 个 `turn_id`
指纹。结合 2 次 `UserPromptSubmit`，现有聚合证据支持把 `session_id`
作为同一 Codex 任务的稳定身份候选，把 `turn_id` 作为执行轮次候选。
双任务采集仍需验证不同任务的 `session_id` 是否互不相同。

## 初步状态映射

| 事件 | 标准状态 | Halo 默认表现 |
|---|---|---|
| `UserPromptSubmit` | 执行中 | 对应圆环开始黄色追逐 |
| `PreToolUse` / `PostToolUse` | 执行中、刷新活跃时间 | 黄色追逐保持流动 |
| `Stop` | 轮次结束候选 | 暂映射为绿色完成提示 |

本次采集到 1 个 `Stop`。按 Hook 定义暂作轮次结束候选，但聚合报告不验证它的
事件顺序，也尚未证明它能区分任务永久完成、用户中止或异常结束；生产状态机应
保留超时校准和后续事件修正能力。

## Gate 结果

**单任务候选 Gate：PASS（进入双任务验证）**

- 单任务的 16 个事件中只有 1 个 `session_id` 指纹，符合稳定任务身份候选预期。
- 样本中有 2 个 `turn_id` 指纹和 2 次 `UserPromptSubmit`，符合轮次候选预期；
  聚合报告尚不证明两者逐轮一一对应。
- 已采集到执行开始、工具活动和轮次结束候选信号；聚合报告不主张事件顺序。
- 全部证据满足既定隐私边界。

## 限制与下一步

单任务候选 Gate 阶段尚未验证：

- `PermissionRequest` 是否能可靠表示等待用户审批。
- 两个并发任务是否具有不同且各自稳定的 `session_id`。
- 异常失败、用户中止、任务重命名和 Codex 重启后的身份连续性。
- `Stop` 与“任务完成”之间是否需要任务列表或超时规则进一步校准。

当时的下一步计划是执行双任务并发采集：在两个任务中制造交错的只读工具活动，比较
`session_id` 指纹是否稳定且互不相同，并确认每个 `Stop` 能归属到正确任务。
只有双任务 Gate 通过后，才进入自动四环绑定与桌面状态机实现。

## 双任务结果

双任务匿名聚合报告见
[`2026-07-26-two-task-analysis.json`](./2026-07-26-two-task-analysis.json)。

本轮共分析 76 个有效事件，选定 `$.session_id` 作为任务身份候选。两个匿名
会话组的事件范围发生重叠：

| 匿名组 | 事件数 | Hook 构成 | 事件索引范围 |
|---|---:|---|---:|
| `group_1` | 47 | `PreToolUse` 22、`PostToolUse` 22、`Stop` 1、`UserPromptSubmit` 2 | 1–76 |
| `group_2` | 29 | `PreToolUse` 13、`PostToolUse` 13、`SessionStart` 1、`Stop` 1、`UserPromptSubmit` 1 | 6–58 |

报告未触发文件数量上限，`anonymous_group_labels_comparable` 为 `true`。
`group_1` 有 47 个事件，而索引 6–58 之外最多只有 23 个位置，因此两组在该区间内
都实际出现了事件，说明采集窗口中两组生命周期事件发生了交错。
运行时另观察到 Codex 任务列表中的 A、B 两个任务同时处于 active，B 完成耗时
约 390 秒；这是采集时的运行时观察，不是匿名聚合 JSON 中的字段。

两个 `session_id` 匿名组互不相同，各组内部均覆盖工具开始、工具结束和各自的
`Stop`，因此轮次结束信号可以归属到对应任务。完成这项映射不需要提示词、代码、
工具参数或任何原始 ID。

`$.cwd` 同样形成 2 个匿名组，但不能作为任务身份：不同任务可以共享同一个工作
目录，目录变化也不等于任务身份变化。`$.turn_id` 在本轮形成 4 个匿名组，只适合
表示轮次，不适合作为跨轮次的任务主键。

**双任务身份 Gate：PASS**

- 同一匿名 `session_id` 在各自任务的生命周期事件中保持稳定。
- 两个任务的 `session_id` 互不相同，且活动范围实际重叠。
- 两组都包含 `PreToolUse`、`PostToolUse` 和可独立归属的 `Stop`。
- 身份区分和完成归属均不依赖敏感内容或原始标识。

本轮还发现 `tool_name` 原样及长度可能泄露诊断细节，现已将名称归一化为
`present`，并将结构摘要中的名称字段标记为已脱敏。全量测试共 64 项，其中
63 项通过，1 项因当前 Windows 会话缺少符号链接权限而跳过。

仍有以下边界尚未验证：

- `Stop` 仅表示轮次完成，不能直接等同于整个任务永久结束。
- `PermissionRequest` 是否能稳定表示等待用户审批。
- 异常失败能否由现有生命周期事件可靠区分。
- Codex 或桌面驱动重启后的任务身份连续性。

## 下一步适配器决策

生产 Hook 适配器以 `session_id` 作为任务主键，`turn_id` 仅作为轮次标识。
原始 `session_id` 只允许用于本机内存中的实时路由或本地映射；持久化记录和诊断
报告只能保存匿名标签或不可逆指纹，不保存原始值。

双任务身份 Gate 已通过，可以开始自动四环绑定与桌面状态机 MVP：先实现
`session_id` 到圆环槽位的自动分配、活跃度刷新、轮次完成提示和手动锁定，再用
虚拟设备验证混合绑定模式。等待审批、错误状态和重启恢复应作为后续独立验证项，
不能在尚无证据时假定已经可靠。
