# Codex Halo USB CDC 协议 v0.1

**协议主版本：** 1  
**协议次版本：** 0  
**传输：** USB CDC 串行字节流  
**整数顺序：** 小端序

本文档冻结桌面驱动和 ESP32-S3 固件之间的 v0.1 二进制边界。设备只接收渲染所需的脱敏状态，不接收任务原始身份、提示词、回答、代码、命令、工具参数、路径、环境变量、凭据或 USB 序列号。

## 1. 帧格式

每个帧由固定 8 字节头部、0–512 字节负载和 2 字节 CRC 组成。最小帧为 10 字节，最大帧为 522 字节。

| 偏移 | 大小 | 字段 | 编码与约束 |
|---:|---:|---|---|
| 0 | 2 | `magic` | 固定为 `43 48`，即 ASCII `CH` |
| 2 | 1 | `protocolMajor` | 固定为 `01` |
| 3 | 1 | `messageType` | 见消息类型表 |
| 4 | 2 | `sequence` | `u16` 小端序；由每个发送方向独立递增，回绕遵循 `u16` |
| 6 | 2 | `payloadLength` | `u16` 小端序；必须不大于 512 |
| 8 | N | `payload` | 消息负载，N 等于 `payloadLength` |
| 8+N | 2 | `crc` | CRC-16/CCITT-FALSE 结果的小端序表示 |

CRC 参数固定如下：

| 参数 | 值 |
|---|---|
| 名称 | CRC-16/CCITT-FALSE |
| 多项式 | `0x1021` |
| 初始值 | `0xFFFF` |
| 输入反射 | 否 |
| 输出反射 | 否 |
| 最终异或 | `0x0000` |
| 覆盖范围 | 从偏移 2 的 `protocolMajor` 到负载末尾；不含魔数和 CRC |

接收器必须逐字节重同步：丢弃魔数前的噪声，半帧继续保留；只有收齐 8 字节头部后才读取长度。长度超过 512 时立即拒绝当前候选帧，不得按声明长度分配内存。CRC 错误后丢弃当前候选魔数并继续寻找下一组 `43 48`。

## 2. 消息类型

| 值 | 名称 | 方向 | 是否要求 ACK |
|---:|---|---|---|
| `01` | `HELLO` | 桌面端 → 设备 | 否，以 `CAPABILITIES` 响应 |
| `02` | `CAPABILITIES` | 设备 → 桌面端 | 否 |
| `10` | `FULL_SNAPSHOT` | 桌面端 → 设备 | 是 |
| `11` | `RING_UPDATE` | 桌面端 → 设备 | 是 |
| `12` | `DISPLAY_MODE` | 桌面端 → 设备 | 是 |
| `13` | `BRIGHTNESS` | 桌面端 → 设备 | 是 |
| `20` | `HEARTBEAT` | 桌面端 → 设备 | 否 |
| `70` | `ACK` | 双向 | 否 |
| `71` | `NACK` | 双向 | 否 |
| `80` | `KNOB_EVENT` | 设备 → 桌面端 | 否 |
| `81` | `DIAGNOSTICS` | 双向 | 否 |

状态写入的 `ACK` 或 `NACK` 必须复用被确认帧的 `sequence`。桌面端的 ACK 等待时间为 250 ms，失败最多重试 2 次；心跳间隔为 1000 ms，设备通信看门狗为 3000 ms。

`DIAGNOSTICS` 是唯一的双向非状态消息，其收发规则为规范要求：

- 收到格式合法的诊断必须静默消费：不得回复 `ACK`，不得刷新设备通信看门狗，不得改变权威呈现状态，也不得清除本端尚未发出的诊断。
- 收到格式非法的诊断按接收方角色处理。固件复用该帧 `sequence` 回复 `NACK`，其 `rejectedMessageType` 为 `81`、`reason` 为 `01`（`malformedPayload`）；桌面端不回复 `NACK`，而是发送一条代码为 `0003` 的诊断。两端都不得用诊断回复诊断以外的方式互相追问，避免形成回复循环。
- 因此 `rejectedMessageType` 为 `81` 的 `NACK` 属于合法线路流量，接收方不得把它当作状态写入的应答。
- 发送方必须限制协议错误诊断的频率：桌面端每个 manager step 最多发送一条；固件按代码合并到固定槽位，不使用无界队列。

## 3. 基础类型和状态枚举

未特别说明时，所有百分比字段的有效范围均为 0–100。`speedPercent` 是唯一例外，有效范围为 25–300，表示 0.25×–3.00×。越界值属于格式错误。

### 3.1 显示模式

| 值 | 状态 |
|---:|---|
| `00` | `ambient`，极简 Codex 图标 |
| `01` | `overview`，四圈总览 |
| `02` | `detail`，所选圆环详情 |

`selectedRing` 使用 `00`–`03` 表示对应圆环，`FF` 表示未选择。

### 3.2 任务呈现状态

| 值 | 状态 |
|---:|---|
| `01` | `running` |
| `02` | `waiting` |
| `03` | `roundCompleted` |
| `04` | `failed` |
| `05` | `queued` |
| `06` | `idle` |
| `07` | `unknown` |

### 3.3 动画方向

| 值 | 方向 |
|---:|---|
| `00` | `clockwise` |
| `01` | `counterClockwise` |

### 3.4 NACK 原因

| 值 | 原因 |
|---:|---|
| `01` | `malformedPayload` |
| `02` | `unsupportedMessage` |
| `03` | `invalidState` |
| `04` | `busy` |
| `05` | `internalError` |

### 3.5 旋钮动作

| 值 | 动作 |
|---:|---|
| `01` | `rotate` |
| `02` | `shortPress` |
| `03` | `longPress` |

### 3.6 诊断级别和代码

诊断负载不传输自由文本，避免泄露桌面信息。

| 级别值 | 级别 |
|---:|---|
| `01` | `info` |
| `02` | `warning` |
| `03` | `error` |

| 代码值 | 含义 |
|---:|---|
| `0001` | 看门狗进入断连状态 |
| `0002` | CRC 错误 |
| `0003` | 负载无效 |
| `0004` | 本地电流或亮度限制生效 |

代码始终相对于发送方描述其本地状况，与方向无关：设备发出的 `0002` 表示设备解析桌面端字节流时遇到 CRC 错误，桌面端发出的 `0002` 表示桌面端解析设备字节流时遇到 CRC 错误。接收方不得把对端代码理解为对自己的指控。

`value` 的含义由代码固定，两个方向可以不同，但都不得携带敏感信息：

| 代码值 | 设备发送时的 `severity` 与 `value` | 桌面端发送时的 `severity` 与 `value` |
|---:|---|---|
| `0001` | `02`；看门狗超时毫秒数 | 不发送 |
| `0002` | `02`；饱和累计的 CRC 错误次数 | `02`；固定为 1 |
| `0003` | `02`；饱和累计的无效负载次数 | `02`；固定为 1 |
| `0004` | `01`；限制生效后的有效亮度 | 不发送 |

## 4. 消息负载

下列布局中的多字节整数均为小端序。除明确的可变长度字段外，接收器必须拒绝长度不完全匹配的负载。

### 4.1 `HELLO` (`01`)

| 偏移 | 类型 | 字段 | v0.1 值 |
|---:|---|---|---|
| 0 | `u8` | `protocolMinor` | `00` |

### 4.2 `CAPABILITIES` (`02`)

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `u8` | `protocolMinor` |
| 1 | `u8` | `firmwareMajor` |
| 2 | `u8` | `firmwareMinor` |
| 3 | `u8` | `firmwarePatch` |
| 4 | `u8` | `ringCount`，首版固定为 4 |
| 5 | `u16` | `featureFlags`；bit 0 为 AMOLED，bit 1 为旋钮 |
| 7 | `u16` | `maxPayload`，不得大于 512 |

总长度为 9 字节。v0.1 模拟设备返回 `00 00 01 00 04 03 00 00 02`。

### 4.3 圆环记录 `RING`

`RING` 不是独立消息，而是 `FULL_SNAPSHOT` 和 `RING_UPDATE` 共用的记录：

| 相对偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `u8` | `index`，范围 0–3 |
| 1 | `u8` | `status` |
| 2 | `u8` | `brightness` |
| 3 | `u16` | `speedPercent`，范围 25–300 |
| 5 | `u8` | `direction` |
| 6 | `u8` | `tailPercent` |
| 7 | `u8` | `labelLength`，v0.1 固定为 0 |
| 8 | bytes | `label`，v0.1 固定为空 |

v0.1 保留标签字段，但桌面端编码边界必须拒绝非空标签。标签不得从任务身份、提示词、回答、代码或路径生成。

### 4.4 `FULL_SNAPSHOT` (`10`)

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `u64` | `revision` |
| 8 | `u8` | `globalBrightness` |
| 9 | `u8` | `displayMode` |
| 10 | `u8` | `selectedRing` |
| 11 | `u8` | `ringCount`，v0.1 固定为 4 |
| 12 | `RING[]` | 紧接 `ringCount` 个可变长度圆环记录 |

每次建立或恢复连接时，该消息都是覆盖设备残留状态的权威快照。

### 4.5 `RING_UPDATE` (`11`)

负载恰好包含一个完整 `RING` 记录。

### 4.6 `DISPLAY_MODE` (`12`)

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `u8` | `displayMode` |
| 1 | `u8` | `selectedRing` |

总长度为 2 字节。

### 4.7 `BRIGHTNESS` (`13`)

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `u8` | `globalBrightness` |

总长度为 1 字节。设备仍必须执行本地电流预算和亮度硬上限。

### 4.8 `HEARTBEAT` (`20`)

空负载。

### 4.9 `ACK` (`70`)

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `u8` | `acknowledgedMessageType` |

总长度为 1 字节。

### 4.10 `NACK` (`71`)

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `u8` | `rejectedMessageType` |
| 1 | `u8` | `reason` |

总长度为 2 字节。

### 4.11 `KNOB_EVENT` (`80`)

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `u8` | `action` |
| 1 | `i8` | `delta`；旋转时为非零步数，按压时固定为 0 |

总长度为 2 字节。帧序号用于桌面端丢弃已经处理的旧事件；固件只负责消抖和上报，不解释任务选择等产品语义。

### 4.12 `DIAGNOSTICS` (`81`)

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `u8` | `severity` |
| 1 | `u16` | `code` |
| 3 | `u32` | `value`，与代码相关的非敏感数值 |

总长度必须精确为 7 字节。`severity` 与 `code` 必须取 3.6 中定义的值，长度、级别或代码任一不匹配都属于格式错误，按 2 中的诊断规则处理。诊断消息不得包含自由文本、完整帧负载、任务信息或串口序列号。

## 5. 版本兼容

- 帧头的 `protocolMajor` 不等于 1 时，接收器返回结构化的不兼容错误，并停止状态写入。
- 同一主版本内，通过 `HELLO` 和 `CAPABILITIES` 的 `protocolMinor` 协商共同支持的最低功能集。
- v0.1 的次版本为 0；更高次版本设备必须仍能使用本文件定义的固定 v0.1 负载，否则不得声明主版本 1 兼容。
- 未知消息类型必须作为结构化错误处理，不能解释为已知消息或静默修改设备状态。
- 未知能力位必须忽略；发送端只能使用双方声明支持的能力。
- 固定负载不得通过尾部追加字段实现扩展。需要改变布局时必须定义新的消息类型或提高协议主版本。

## 6. 黄金向量

以下内容与同目录的 `golden-vectors.tsv` 完全一致。`sequence` 和帧中的多字节字段按小端序编码，但表格把逻辑序号写成人类可读的四位十六进制数。

| name | message_type | sequence | payload_hex | frame_hex |
|---|---|---|---|---|
| hello | `01` | `0001` | `00` | `4348010101000100006e91` |
| heartbeat | `20` | `0002` | 空 | `43480120020000006cae` |
| ack_hello | `70` | `0001` | `01` | `4348017001000100017381` |
| brightness_80 | `13` | `1234` | `50` | `4348011334120100502983` |

例如 `hello` 的 CRC 覆盖字节为 `01 01 01 00 01 00 00`，计算结果为 `0x916E`，在线路上按小端序写为 `6E 91`。
